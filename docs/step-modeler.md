# STEP editing, the kernel crate

`docs/step-modeler-evaluation.md` is the decision. This note is the contract for the first change: a kernel crate that dynamically links Open CASCADE Technology 7.9.2. Model mode, picking, measure, and the edits themselves are later changes. `crates/lime-slice-core` is not part of this work.

## What this change is

`crates/lime-model` is the swap point. `Kernel` is the trait. `open()` loads a session.

`OCCT_ROOT` selects the install. When it is set, the build links `TKernel` with `cargo:rustc-link-lib=dylib` and `open()` returns the string from `OCCT_Version_String_Complete()`. When it is unset, the C++ compiler is not run and `open()` returns an error. A static archive of `TKernel` fails the build.

The core, the `lime-slice` CLI, and the Tauri shell do not depend on this crate. Opening the app and slicing a file stay on the path they have today. Truck remains the reader of an unedited STEP file. An edited solid, when that exists, will tessellate into the existing `sourcePos` / `encodeStl` path.

`tools/occt/install.py` compiles tag `V7_9_2` as shared libraries. The pin, the archive URL, and the SHA-256 are in `third_party/occt/NOTICE.md`. The toolkit list is the modeling set through `TKMesh` and `TKShHealing`, plus `TKDESTEP` so Model mode can read a solid. CMake pulls `TKXCAF`, `TKV3d`, and `TKService` for that reader. FreeType and OpenGL stay off, and those toolkits build without them. STEP write is still a later change.

`tools/occt/stage_bundle.py` copies those shared libraries and the three notice files. The release workflow stages them at `src-tauri/resources/occt` and passes `src-tauri/tauri.occt.json`, which bundles that directory as `occt/`. A local `tauri build` does not pass that overlay and does not need OCCT. The staged directory is gitignored.

## How the libraries are linked

The link is dynamic on every platform.

- Linux: `libTKernel.so`, rpath `$ORIGIN`.
- macOS: `libTKernel.dylib`, install name `@rpath`, rpath `@executable_path` and `@executable_path/../Resources/occt/lib`.
- Windows: import library `TKernel.lib` at link time, `TKernel.dll` at run time.

`LIME_REQUIRE_OCCT=1` makes a missing library a test failure. The test reads the dynamic imports of its own executable (`ldd`, `otool -L`, or the PE import table) and requires `TKernel` there. CI runs that test on Ubuntu, inside the existing Rust job, and on `windows-latest` and `macos-latest`. The Ubuntu job is one of the required checks. The other two are not, so a merge waits for them on purpose.

The notices shipped beside the libraries are `third_party/occt/LICENSE_LGPL_21.txt`, `OCCT_LGPL_EXCEPTION.txt`, and `NOTICE.md`. The source offer is the official archive plus `tools/occt/install.py`, for at least three years after a release that includes the libraries. The rest of Lime Slice stays MIT. No GPL code is linked. SolveSpace is not a dependency.

The Intel macOS installer is the existing cross compile from the Apple silicon runner. That job builds the OCCT dylibs with `CMAKE_OSX_ARCHITECTURES=x86_64` and stages them. The native macOS CI job is arm64. The shell still does not link OCCT, so a missing dylib cannot stop the app from starting.

## Model mode

The fourth workspace tab is Model. It is not selected when the app opens. Shortcut `4`. Shift+4 stays the By layer strategy.

`crates/lime-model-occt` is a cdylib. It links the modeling toolkits and, when `libTKDESTEP` is present, the STEP reader. `crates/lime-model-load` dlopens that library. The CLI and the Tauri shell depend on the loader only, so a missing bridge cannot stop the app from starting. The shell looks beside the executable and in `occt/lib` under the resource directory. `LIME_OCCT_BRIDGE` overrides the path.

Model mode opens the object's STEP as the root of its history tree (`open` on `POST /api/model/tree`, or the `model_tree` command; see "History tree" below). The reply is the solid's tessellation, volume, face areas, and edge polylines. A STEP of surfaces with no closed solid replies `solid: false`: the readout says it can be measured but not edited, shows no volume, and every tool but Measure is off. A click selects one face or edge and reports its area or length. Shift-click adds or removes a pick. Exactly two picks report the distance. Escape, or a click on empty space, clears the selection. Edits open from the toolbar and run on Apply, which closes the tool. The tool's ghost in the view is a local stand-in; the result drawn in the solid's place while a tool is open is the kernel's dry-run ("The preview"). With no solid to show (an empty plate, or a selected object that is a mesh), the view says so in a card in its middle, with New solid and Open a file, and draws every plate object grey; see "New solid". Nothing is invented when the bridge is missing.

With more than one object on the plate, the others are drawn grey where they sit in model space (below). They are not part of any pick, snap, handle drag, framing, bed centring, or size readout, and no tool targets them but Boolean on an object, which picks its tool among them ("Booleans between objects"). The canvas carries `data-context-count` and `data-context` (each object's id and model-space box), `data-solid` (the open solid's model-space box), `data-context-screen` and `data-solid-screen` (their screen boxes), and `data-camera` for tests.

## Model space

Model draws every object in one shared frame, model space, apart from the plate layout that prints them (`src/model-space.ts`). The plate pose (orient, offset, placement scale, Arrange) plays no part in it, and nothing done in model space changes the plate, the mesh, or the slice.

- **Pose.** Each plate object has `modelPose`, a rigid pose from its own CAD frame into model space (an `Affine`; only a Separate-shells piece of a scaled part carries a scale, and those are meshes Model does not open). Absent is identity: an imported STEP or STL sits at its own file coordinates, so parts exported from one CAD assembly line up as designed, and unrelated files can overlap or sit far apart.
- **Seat.** The slicer lowers every mesh onto Z = 0 when it reads it. The amount, the mesh's seat, is kept by mesh token (`meshSeat`), so model space puts the mesh back up into its CAD frame before the pose. An STL's seat is known when the app reads it; a STEP or 3MF the slicer reads (`/api/mesh`, or the desktop's `preview_mesh`) comes back with `seatMm`, how far the reader lowered it; a mesh Model writes for a step or a split piece knows its solid's lowest point. So every import, and every piece Separate into plate objects cuts from one, sits at its file's own coordinates in model space from the start. An engine from before `seatMm` leaves a STEP's seat unknown, counted as 0 until Model first shows that object and learns it from the solid; pieces Separate cuts from such a file before then keep that 0 for good, since Model never opens a piece. A 3MF from such an engine keeps 0 for good too, since Model does not open a mesh. A Model-edited part, whose plate mesh is an STL saved already lowered, from a file saved before seats existed is learned the same way as such a STEP. A seat is taken only once its read still applies: a read that a newer Open, Add, or selection overtook changes nothing.
- **Split.** A split piece takes its parent's pose, so it sits exactly where it was cut, and the parent's other half sits right under or over it. On the plate both pieces still land on the bed in one spot, and Arrange lays them side by side.
- **Duplicate.** A copy takes the source's pose moved along model X by the source's own model-space width plus 10 mm (`DUPLICATE_GAP_MM`), so it sits beside the original instead of inside it. The plate pose is copied as before.
- **Separate shells.** Each piece keeps the place it had inside the part.
- **Tools.** Every number a tool takes or a handle drags is in model space: the Boolean primitive's origin and turn, the Hole's origin and axis, the Split plane, the Measure points. Before an engine call `toSolidOp` turns the op into the open solid's own frame with the inverse of its pose. A box or cylinder turns about its centre, so that centre goes through the inverse pose and the turn takes the pose's turn. With an identity pose, as in every file saved before this, the op is the one typed, number for number. Stored ops, probes, replay, and `.lime` trees stay in the solid's frame. The axis triad and the dock arrows are model space. A part with a local workplane (`docs/local-workplane.md`) has Boolean's and Hole's origin, Boolean's turn, and Split's X, Y and Z in its U, V, W instead, one step before `toSolidOp`.
- **History labels** name a step in the part's own frame, from the stored op alone, so moving a part later never renames its steps and a saved or replayed op labels as it did. With no pose the label shows the number typed. A Split typed along model Z on a part raised 10 mm reads "Split at Z 5"; on a part lying on its side it can land on another axis of the part ("Split at Y 15"), and on a part turned 30° about X it is a tilted plane of the part ("Split at Z 17.32, tilt −30° / 0°").
- **Place** (toolbar, Shift+P) moves and turns the open object in model space. X, Y and Z are how far its centre sits from where its file put it; Turn X, Y and Z turn it about that centre, in the order a primitive turns. The dock arrows and rings drag them. A field changes only itself: the other fields keep the pose's exact values, not the rounded ones shown, so a move never turns the part and never nudges another axis. A turn field keeps the other two angles as the pose has them, except within a hair of Turn Y ±90°, where X and Z share one turn and the other angle can shift while the part turns as typed. A field cleared or half typed moves nothing until it holds a number. Place runs on surfaces with no closed solid too, has no Apply, and its button reads Done. A Place gesture (one drag until the pointer lets go, or a typed or scrubbed number once it rests 400 ms) is one step: while Place is open, Undo and Redo (the buttons, Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y) step its moves, and the solid's history waits until it closes. A gesture that ends where it began is no step. Each step is also a Prepare step, folded into the visit like an edit, so Prepare undo takes back a visit's moves with its edits. It is not a Model history node, because a node is a kernel op the engine replays per solid, and the pose belongs to the plate object rather than to any one step of its solid. History shows it instead in its Position row, which opens Place and resets the pose ("History panel").
- **Bed.** The bed and build volume are drawn faintly as a size reference, centred under the open object with the plate at its lowest point in model space, as before. They do not take part in model space, and the grid moves rather than being rebuilt as the part moves. The size chip and its fit warning read the part's own box, since where the part sits or turns in model space does not change what prints. The Bed button in the toolbar hides and shows them, and the choice stays for that browser (`localStorage`).
- **Camera.** Model frames the open object, in model space, from the front right and above, the first time it shows that object. A new solid of the same object (an Apply, a jump, Undo) keeps the user's view. Reset view (the button at the head of the size chip and readout column, under History, or Home) goes back to that framing; Shift+click or Shift+Home frames every object. The Objects list's Frame frames that object in Model and stays in Model. All of them share one framing function.
- **Cost.** Each grey object's matrix is composed when the plate or the open object changes, never per frame; the meshes keep their buffers and move by a matrix. The open solid's model-space box is computed once per solid and pose and shared by every tool, handle and note.
- **Saved.** `.lime` keeps `modelPose` (`{m, t}`) and `meshSeatMm` on each object, both optional. A file without them opens at identity. A pose that is not a turn times one uniform scale (a shear, a mirror, a collapse) is a damaged file. One object with a pose is written as version 2.

## New solid

A solid can start from a primitive instead of a file: on an empty plate, with an STL selected, or with another solid open. It becomes a plate object of its own, with a history tree of its own whose root is the primitive, so no file is read. From then on it is a solid like any opened STEP: every tool, History, Place, the STEP button, slicing through the plate commit, Duplicate, and `.lime` save and reopen.

- **Where it starts.** New solid is the first button of the Model toolbar, always there (Shift+N), because that bar is where Model's actions are. While a solid's tools fill the bar it shows its icon only, with its name in the tip, as STEP, Undo, Redo and Bed always do, so the bar still fits at 1440 px with Workplane and a pick's chip. With no solid to show, the card in the middle of the view offers it as its main button, beside Open a file (Add a file once the plate has objects, so the card never replaces them); the readout stays empty then, rather than repeat the card. The card gives way to any open tool, and shows only while nothing can be opened: never while a STEP is read or after an engine error.
- **The panel** is the Boolean tool's: the same primitive buttons (a row of icons, each named in its label and tip, arrow keys move between them), the same size fields and their scrub and drag knobs, the same ghost code. It has no origin and no turn, since the solid places itself, and its Apply reads Create. The note says where it lands. Create asks the engine once; a size the engine refuses goes to the readout with the panel still open.
- **Primitives**: box, cylinder, sphere, cone, torus, wedge, polygon prism, and tube, with the fields of the table under "History tree (engine)". The Radius field is named for what it is on each (Bottom radius, Ring radius, Outer radius), and Across flats or Across corners follows the polygon's toggle, Flats by default since that is how a nut pocket is sized. Sides drags in whole numbers. No other OCCT primitive earned a place: `BRepPrimAPI_MakeHalfSpace` is what Split already does, a sphere segment (a dome) is a sphere and one Split, and `MakeRevol` or a free `MakePrism` need a sketch, which is not part of this.
- **The root** is the primitive standing centred over its own origin, its lowest point on Z = 0, untilted (`rootSpec` in `src/model-primitive.ts`), so its own frame is a printable one. It keeps only the fields its kind reads; the rest are 0. The engine builds it on `open` from `primitive`, and again on every replay, checking it against the root's fingerprint; a root that builds differently says so in its own words, since the root cannot be dropped. A size within 1e-6 mm of 0 is 0 to the engine (a hole that thin is a solid tube), and a size that must be there and is that small is refused.
- **Where it goes.** In model space it stands at the origin when model space is empty, else beside everything, as Duplicate puts a copy: along +X, 10 mm (`DUPLICATE_GAP_MM`) past the farthest object, centred on their Y, on their floor (`newSolidPose`). The open object counts as the view shows it, edits not yet on the plate included, so the ghost stands exactly where Create puts it. On the plate it goes where an added file goes, the first clear shelf slot, or centred on the bed when the plate is empty. Its plate mesh is its tessellation as an STL, as for an edited step.
- **The name** is the primitive's and the first number no object has with it: Box 1, Box 2, Cone 1 (`primitiveName`). The root's History row names the primitive and its sizes: "Cone ⌀20 to ⌀8 h 30".
- **Undo.** Creating is a Prepare step, folded into the Model visit like an edit: Prepare undo takes the visit back, the object with it, and its tree stays while redo can bring it back. A solid created on an empty plate leaves an empty plate again; only a step taken before any file was loaded (`meshless`) empties the plate, so a step taken while a file is still being read never does.
- **The view.** With nothing open, opening New solid looks at where the solid will land, and so does a settled number or a picked primitive that grows it out of view; while a number is typed or dragged the view stays put. Create opens the new solid and frames it.
- **Cost.** The ghost is built on the client from the sizes alone, and only when a size changes (`primitiveMesh`); its shaded and edge geometry are built once per mesh, so a move or a turn only moves them. Nothing asks the engine until Create. Each plate mesh's own box is read once. The new solid's STEP is written as an edited step's is, on leaving Model, at a save, or by the STEP button, and is kept as its `brep`, so an app without primitive roots still opens the part; the tree itself never reads it.
- **A copy** (Duplicate) of a new solid on its root starts from the same primitive, with no STEP written or read, even once the root has a STEP.

## Booleans between objects

The Boolean tool fuses, cuts, or intersects the open solid with another plate object as well as with a primitive: a split piece, an import, or a New solid. The owner asked for it on 2026-10-15, and decided that it asks per op and that the tool object leaves the plate unless "Keep the tool object" is ticked.

- **The panel.** Boolean's choice of what it combines with is its primitive row: a primitive, as before, or Object, the row's last button (New solid does not show it). It stays one tool rather than a second one, since the op, the Fuse / Cut / Common buttons, the dry-run and Apply are the same, and the toolbar has no room to spare at 1440 px; and Object sits in the row rather than in a Primitive / Object switch of its own, so the panel gains no row: at 1280 × 640 History keeps room for its rows under the open panel, and the phone sheet still shows a row of fields above its buttons. Picking a primitive again goes back to it. Shift+G opens Boolean on an object (G stays Boolean; Shift+G was free in every scope). With Object chosen the primitive's fields hide, and a short list names the other plate objects that can be the tool; a click on a grey object in the view picks it as well. A click on a grey object that cannot be the tool says why in the readout ("cube.stl is a mesh, so it cannot be a tool."). The pick is drawn as the ghost, where it sits in model space, from the grey object's own buffers moved by its matrix and flat-shaded as the grey objects are, and it is no longer drawn grey; its outline is found once per mesh, and not at all past 150 000 triangles, where finding it would hold up the pick. Under Fuse, Cut and Common is "Keep the tool object", off whenever Boolean opens and after each join, since the owner asked for the choice per op. The readout says what will happen: "Cut telo split from telo.stp; telo split leaves the plate.", "Fuse Box 1 into telo.stp; …", "Intersect telo.stp with Box 1; …", Intersect as the History label says it. The note under the panel carries the dry-run as for a primitive. No handle drags the tool; Place moves it, on its own.
- **What is offered.** Only solids: an object Model has opened as a solid, or a STEP, a New solid or a copy of one that it can open. A mesh (STL, 3MF) is not offered, nor surfaces with no closed solid once Model has seen them; an object picked before Model opened it gets its tree then, and if it turns out to be surfaces it leaves the list with the reason in the readout. The open object is never its own tool. A tool whose history already uses the open solid (it joined it, at any depth) is refused with "The tool object's history already uses this part, so the two cannot be joined." The refusal is per tree, not per step: two trees that each named the other could neither be closed nor have that join's branch deleted, since the engine keeps every tree and step a join names. So the brief's narrower case (a tool step that itself depends on the open solid) is refused, and so is a step that does not, which is the price of that rule.
- **Op.** `{kind: "join", op: "fuse" | "cut" | "common", tool: {object, key, node, name}, relative: {m, t}, keepTool}`. `tool.key` and `tool.node` name the tool object's tree and the step its plate mesh is, at Apply. `relative` is the tool's pose in the target's own frame, the target's inverse model pose then the tool's (`relativePose` in `src/model-space.ts`, built by `joinOp` in `src/model-request.ts`), worked out once at Apply and stored, so moving either object later never moves a cut already made. A tool whose tree moves on after Apply keeps the step the join named.
- **History.** The join's row is a merge: the steps that made its tool come in on a lane of their own, can be looked at, and can be edited from there ("A tool's steps in History").
- **Labels** come from the stored op: "Cut telo split", "Fuse Box 1", "Intersect Sphere 1". The tool's name is captured at Apply (`tool.name`), not looked up, because the tool usually leaves the plate, where there is nothing to look it up on, and because a label must read the same after a rename, a save, or a replay, as every other label does.
- **Engine.** `apply` and `probe` take the join; the engine builds the tool's step from its own tree (its kept solid when it holds one), places it by a location built from a unit quaternion, so nothing is copied and the location carries no scale, and runs the boolean as for a primitive. `relative` must be a turn and a move, within 1e-6: a scale, a shear or a mirror is refused with "The tool's placement must be a turn and a move only, with no scale, shear, or mirror". Replay of a target's join asks the tool tree for its step, so one tree's step depends on another's. A tool tree or step the engine does not hold answers `{error: "The tool object's history is not open in the modeler", missingTool: {key, node}}`, with `broken: id` when a step of the tree asked about cannot be built for it; nothing is marked, so once the client opens that tree the same call works. `close` refuses a tree that a join in another tree takes its tool from, and `drop` a branch with such a step. A join's `keepTool` and its tool's `object` and `name` build nothing, so a probe and an Apply that differ only there share one build.
- **Plate.** With Keep off, Apply takes the tool off the plate in the visit's Prepare step, the one that holds the target's change, so Prepare undo puts it back with its pose, paint and tree key. An Apply of the same join from the same step, which shows the step it built before, takes the tool off too. Undo in Model above the join leaves the tool wherever the plate has it, and the plate taking the join's step again never takes the tool off: only Apply does, since taking an object off the plate behind the user's back would surprise more than leaving one there. A split piece fused or cut back into its own part in the same visit stays off the plate when the plate takes that step, rather than come back as a split's piece does.
- **Trees.** A tree stays while a join names it, on the plate or not (`reachableTrees`), and the client closes trees each before the trees its joins take a tool from (`closeOrder`), one at a time in one queue, as the engine requires; a close the engine refused goes again after the next. A tree from a project that sits on its STEP-read step is numbered from that step in the engine, so before a call that could build a join naming such a tree's root (a join on the way to the step asked for, the join being applied, or theirs in turn), that tree is opened whole; a join naming any other step of it gets `missingTool`. An engine that answers `missingTool` gets that tree back from its root and ops, once for every call that found it missing at once, and the call goes again; a split piece's tree rebuilt after a restart does the same for its joins. A tool tree that does not come back marks nothing in the client either.
- **Save.** A join names its tool by object id and step, without the engine key. The tool's tree is saved whenever a saved join names it: with its object if that is on the plate, else in `modelTools: [{id, name, modelTree}]` at the top of the file, under the id the join names. On load every tree is adopted after the trees its joins take a tool from (`toolFirst`); the engine opens each when a call first needs it, the tool's when the target's join asks for it (`missingTool`), so a tool's tree is always whole in the engine before a join builds from it. A tree whose join's tool tree is missing or damaged, in the file or in its bytes, is left out, with the notice a damaged tree gets, and so is any tree that took a tool from it; a kept tool no saved join names any more is dropped quietly. A save whose tool tree cannot be written leaves the target's tree out and names it in the notice after the save. A file without joins is written and read as before; an older app reads a join as an unknown op, so it leaves that tree out with its notice and opens the part from its mesh.

## Shipping the bridge

The release workflow builds the cdylib after staging the Open CASCADE libraries and copies it into `src-tauri/resources/occt/lib`, next to those libraries. The cdylib's rpath is `$ORIGIN` on Linux and `@loader_path` on macOS.

On Windows the exe (through the vendored Clipper2 C++) and every Open CASCADE DLL link the Visual C++ runtime dynamically: `msvcp140.dll`, `vcruntime140.dll` and `vcruntime140_1.dll`. A PC without Visual Studio or the VC++ Redistributable has none of them, and the app stops at start with "MSVCP140.dll was not found". The release workflow runs `tools/windows/stage_crt.ps1`, which copies the three DLLs from the runner's Visual Studio redistributable folder into `src-tauri/resources/crt`. It then also passes `src-tauri/tauri.crt.json`, which puts them beside the exe. Microsoft allows this app-local copy. The exe's own folder is the first one Windows searches, both for the exe and for the bridge (`LOAD_LIBRARY_SEARCH_DEFAULT_DIRS`). For a local installer, run the script and add `--config src-tauri/tauri.crt.json`.

## Booleans and a plane split

Model mode can fuse, cut, or intersect the open solid with any primitive New solid offers (box, cylinder, sphere, cone, torus, wedge, polygon prism, or tube), and it can split the solid with a plane. The numbers are millimetres in model space; the engine gets them in the solid's own frame ("Model space"). A kernel failure is the readout, and the solid is left as it was. There is no mesh boolean behind it.

An edit is a new node in the object's tree; the plate takes it when it commits ("History tree (client)"). The plate's mesh for an edited node is the settled tessellation, written with `encodeStl` under a `.stl` name, so truck is not asked to read the edited solid. The pose stays. Support paint, seam paint, and support edits start empty on a node the plate has not held, because they named another surface; going back to a node the plate held puts its paint back. A split keeps the piece on the negative side of the plane and adds the other piece in the parent's place at once, with the same pose, so the two halves are not parked side by side. Both settle onto the bed, so the plate lists them as overlapping and offers Arrange. The second piece is the root of a tree of its own (the engine's `otherKey`), so selecting it opens it in Model with no STEP read, and it can be edited and split again. Undo above the split leaves the piece on the plate.

### The split plane

The Split panel picks the plane's base with X, Y, Z, or Face (`src/model-plane.ts`, pure math in whatever frame it is given). `splitState` in `src/app/model.ts` works the plane out in model space, and `toolOp` takes it into the solid's own frame for the engine ("Model space").

- **X, Y, Z** cut square to that axis. They are the axes the view's triad and the dock's arrows show, which are model space: the view draws the solid's tessellation at its model pose. With an identity pose, as for every file not moved in Place, that is the solid's own frame, so the triad's X is the solid's X and the op's X. The number is the plane's coordinate on that axis in model space, through the solid's centre line. On a local workplane X, Y and Z are its U, V and W, and the line is the axis through the frame's origin (`docs/local-workplane.md`). A picked face is taken into model space by the pose the same way. The solid's extent along the normal, and the extent of its own box's corners that the kernel checks, are both measured along the normal turned back into the solid's frame and moved by the pose, so the window is the kernel's at any turn.
- **Face** cuts parallel to the last picked face, and turns Face picking on whenever it is chosen or Split opens in it. The number is the offset into the part, from the area-weighted middle of the face. A face whose corners leave its plane by more than 0.001 mm is curved and is refused with "Pick a flat face. This one is curved."
- **Tilt A and Tilt B** turn the normal, in degrees, A about the base plane's first in-plane axis u and then B about the second, v. u is the world axis after the base normal's nearest one (X → Y → Z → X), made square to the normal, and v = n × u: a Z plane tilts about X then Y, an X plane about Y then Z, a Y plane about Z then X. The plane turns about its pivot, the point where the base line crosses it, so a tilt does not move the cut away from where it was put. A typed tilt past ±85° is held at ±85°, in the field once it is left and in the plane at once. Split opens untilted, and a new solid starts untilted, since a tilt was about the part it was set on.
- The op is only `{origin, normal}`: the pivot and the turned normal. It names no face, so a replay never depends on face numbering.
- The note gives the legal range of the number and its middle, and a new base puts the number in the middle. A plane is legal when it stays the margin (2 %, at least 0.25 mm) inside both the solid's own extent along the normal and the extent of its bounding box's corners along it, which is how the kernel measures it (`split_reject`), and 0.001 mm more, since the kernel measures its box from the B-rep with tolerance and the pieces' 0.25 mm floor along the normal. That floor reads each piece's vertices first and, only when they show less, its exact surface box: half a torus, a sphere, or a cylinder cut along its axis has every vertex in the cut plane, and was refused as too close to a face (`tests/primitives.rs`). On Telo test the floor costs what it did. On an axis the two extents are the same. Each extent is measured once per solid and normal, and the plane once per panel state, so typing a position measures nothing and one keystroke works the plane out once. `tests/kernel.rs` checks the kernel cuts 0.001 mm inside its margin and refuses 0.001 mm outside it.
- Labels come from the stored origin and normal alone, in the part's own frame ("Model space"), so a saved split reads as it did: the world axis the normal is nearest, where the plane crosses that axis, and the tilts from it, "Split at Z 42, tilt 15° / 0°". When both tilts round to 0° the label is the axis alone, "Split at X 10", so a float32 normal a hair off an axis still reads as that axis. The crossing is a property of the plane, not of its pivot, so two different planes never share a label, even past 45° where the nearest axis changes. A face split reads the same way, from its normal; the offset from the face is not in the op, so it is not in the label.
- X, Y, Z, and F are not Split shortcuts: X is Scale in Model, Y the front view, and F Lay flat.

## Fillet, chamfer, hole, and scale

Model mode can fillet or chamfer the picked edge, cut a cylindrical hole, and scale the solid by one factor. The blend size, the hole radius, and the hole depth are millimetres. Scale is about the solid's centre.

### Hole

The owner asked on 2026-10-15 whether Hole only goes straight down and so duplicates a Boolean cut with a cylinder. It does not: it drills into a face, and it knows Through all and a counterbore, which a cylinder cut does not. A countersink was not asked for and is not offered.

- **Where it drills.** The hole starts at the origin fields and runs into the face picked last, along its inward normal; with no face picked it runs straight down (−Z in model space), or along −W on a local workplane, and an edited step keeps the direction it was applied with until a face is picked. Hole opens in Face picking so a click on the solid picks one, and the note says which it is: "Into the picked face.", "Straight down; click a face to drill into it.", "Along −W; click a face to drill into it." on a tilted workplane, or, for an edited step, "As the step drilled; click a face to drill into another."
- **Through all** (a box under the fields) cuts to wherever the part ends along the axis. The op stores `through: true`, never a length, so a replay after an earlier edit (a taller root, say) still goes all the way: the kernel works the length out once per build from the solid it cuts, the farthest corner of its bounding box along the axis plus 1 mm (`reach_along`, `kThroughMarginMm`). The Depth field is disabled and its knob gone while the box is ticked, and Depth keeps its number for when it is not. The ghost runs the same length, worked out the same way in the solid's own frame from its tessellation's box, read once per solid (`throughLength` in `src/model-hole.ts`); on a curved part that box can differ from the kernel's by the chord.
- **Counterbore** (a second box) adds a wider, shallow bore at the entry: Bore radius and Bore depth, each with a knob. The kernel fuses the two coaxial cylinders into one tool and cuts the part once, so the part's volume is still integrated once per op (two builds: the fuse and the cut). It refuses, in these words, a counterbore no wider than the hole ("The counterbore must be wider than the hole"), a depth not above 0 ("The counterbore needs a positive depth"), and one as deep as the hole or deeper ("The counterbore must be shallower than the hole"): as its plain depth, or with Through all as far as the part reaches, within 0.001 mm. Through all or the plain depth still applies to the hole itself. A through hole with no radius is "A hole needs a positive radius", since it reads no depth.
- **Screw** is a list that fills the fast path: a medium clearance hole of ISO 273, Through all, and a counterbore for an ISO 4762 socket head cap screw, the head's diameter plus 1 mm and its height plus 0.4 mm, so the head sinks just below the face with room for a printed part. It shows the screw the numbers are, else Custom, which only shows.

| Screw | Hole ⌀ | Counterbore ⌀ × depth |
|---|---|---|
| M2 | 2.4 | 4.8 × 2.4 |
| M2.5 | 2.9 | 5.5 × 2.9 |
| M3 | 3.4 | 6.5 × 3.4 |
| M4 | 4.5 | 8 × 4.4 |
| M5 | 5.5 | 9.5 × 5.4 |
| M6 | 6.6 | 11 × 6.4 |
| M8 | 9 | 14 × 8.4 |

- **Op.** `through`, `counterboreRadius`, and `counterboreDepth` are optional and absent when off, so every older op, `.lime` file and probe key reads and keys as before. They are scalars, so `toSolidOp` carries them as they are. Labels: "Hole ⌀5 depth 8", "Hole ⌀5 through", "Hole ⌀3.4 through, counterbore ⌀6.5 × 3.4". A saved counterbore with only one of its numbers, or a `through` that is not true or false, is a damaged tree.

### The dry-run

Fillet and chamfer stay disabled until an edge is picked, and the button's tip says how to pick one. While the numbers change, a dry-run builds the fillet, chamfer, hole, or boolean on a copy and leaves the solid alone. A number being typed or dragged waits 300 ms (`PROBE_WAIT_MS`, sized to typing speed so one number asks once); opening a tool, a pick, the end of a drag, and every other one-off change ask at once. Answers are kept by tree node and numbers (`probeKey`), since a node's shape never changes: undo back to a checked node enables Apply at once. Apply, undo, and redo ask nothing. The numbers just applied leave Apply off, since applying them again would change nothing. The note says it works, or why not, and for a blend the largest size that did. Apply stays off until that check passes. Split and scale are judged from their numbers. The desktop shell runs every Model command off the UI thread. A kernel failure is the readout, and the solid is left as it was. There is no mesh fallback.

A dry-run that works keeps the shape it built; an Apply of the same op on the same node commits that shape instead of building it again. Each resulting shape's volume is integrated once, by the op that made it, and reused for the reply; a scale multiplies the volume by the factor cubed.

### The preview

Every tool shows its result while it is open, as Scale always did; the owner asked for it on 2026-10-16, since only Scale did and that was not consistent.

- **Boolean, Hole, Fillet, Chamfer** (and an edited step of these, and a join): the dry-run asks for its shape (`probe` with `preview`), and the shape it built is drawn in the solid's place, coloured as the solid is. The solid stays under it, hidden, so a click still picks the solid the tool works on, and its picked faces and edges stay outlined over the shape. As in Fusion's preview, a Boolean keeps its tool's translucent outline over the result, which says where the cutter is; the Hole's cylinder and the blend's tube give way to the shape once it is checked, since the shape shows the hole or the round itself and a stand-in over it would hide it. While new numbers are checked (the 300 ms wait, then the kernel) the shape just checked stays and the stand-in comes back over it, so a drag answers at once and the exact shape follows. A check that fails shows the solid as it is, with the reason in the note, as before. The handles stay throughout.
- **Scale** keeps its own preview: the solid drawn scaled about its centre, which is exact for one factor and needs no kernel.
- **Split** builds nothing while it is open, and needs no shape: both pieces keep all the material, so the result is the solid itself with a cut. It shows the two parts it makes instead: the solid is clipped at the plane, the side the part keeps drawn as it is, and the side that becomes a part of its own drawn tinted, over the plane itself. Clipping planes on the GPU, so nothing is built or meshed.
- **Cost.** The probe meshes its shape once, at the chord Apply uses, and the shape keeps what it measured and meshed; an Apply that takes the probe's shape meshes and measures nothing again (`meshes` does not move; `tests/join.rs`). So Apply costs no more than before, and less. The four shapes used last are kept by node, numbers (`probeKey`) and chord, so going back to numbers just checked draws their shape without asking; an answer whose shape left those four is asked again, since the shape is what is shown. The 300 ms wait stays.

**Apply ends the tool.** After an Apply the tool closes: no ghost, panel or handles stay, and Cancel is never needed to put a tool away. Undo takes the step back. Opening the tool again starts from the numbers applied last, for the session, so a run of similar steps stays quick: the fields keep their values, as they always did between tools, and only Split goes back to the middle of the part, untilted, since the part it was set on was just cut. Numbers already applied on the step shown leave Apply off, as before. Edit step's Update closes the same way. Place and Workplane have no Apply and keep Done.

`lime_model_occt::stats()` gives the linked Open CASCADE `version` and counts builds, volume integrations, `tessellations` (replies built rather than taken from the reply cache), `meshes` (shapes meshed), and `descriptions` (shapes whose faces and edges were measured for a reply) for `tests/kernel.rs` and `tests/tree.rs`.

These edits commit as a boolean does. Pose stays, except that a scale sets the plate's `partScale` back to 1 so the part is not scaled twice; going back to a node the plate held puts its placement scale back.

## History tree (engine)

The bridge also keeps Model history as a tree: one tree per plate object, one node per edit, and a new edit from an older node starts a branch instead of dropping the newer steps. The client owns node ids, labels, and which branch Redo follows. The engine keeps what is costly to rebuild. The kernel operations are in `cpp/kernel.cpp`; the tree's nodes are built with them in `cpp/tree.cpp`.

Every call is one JSON request through `lime_occt_tree` (`POST /api/model/tree`, or the `model_tree` command). `call` picks the operation. `key` names the tree, and node 0 is its root.

| `call` | Fields | Answer |
|---|---|---|
| `open` | `key`, one of `dataB64`, `stepPath`, `box: [x, y, z]`, or `primitive` (a primitive, as below); `chordMm`; optional `nodes: [{id, parent, op, fingerprint}]` (parents first) and `current`; optional `fingerprint`, the root's as saved | The reply for `current` (default 0). Saved nodes are registered, not built. Opening an existing key replaces that tree. A root that builds to another fingerprint answers `{error, broken: 0}` and opens nothing. |
| `apply` | `key`, `parent`, `node`, `op`, `chordMm`; `otherKey` for a split | The new node's reply, plus `op` as stored (edge picks resolved) and, for a split with `otherKey`, `other`: the root reply of a new tree under that key. A split without `otherKey` (a replay) sends no piece and does not tessellate it. Applying an existing node with the same parent, op, and `otherKey` is a jump to it; anything else on an existing id is refused. |
| `probe` | `key`, `node`, `op`; optional `preview: true` and `chordMm` | `{ok: true}`, or `{ok: false, error, maxMm?}`: the edit was built on a copy, or why not and, for a blend, the largest size that fits. With `preview`, a build that works also answers `preview`, the built shape's reply at `chordMm` ("The preview"). A probe that works is kept, and an Apply of the same op on the same node commits it, meshing nothing the preview meshed. |
| `edit` | `key`, `parent`, `node`, `op`, `replay: [{id, op}]`, `chordMm`; optional `tools: [{key, parent, node, op, replay}]` | An edited step ("Editable history"): `op` built on `parent` as the new `node`, then each of `replay` on the last that built, in one call, under one lock. The reply is the last step that built, plus `built: [{id, op, fingerprint}]` (each step kept with its solid, its op as stored) and, when a replayed step did not build, `broken: {id, error}`: that step is kept, marked broken, with the rest of `replay` unbuilt under it. Only the last step that built is tessellated. A kept probe of `op` on `parent` is reused, as by Apply. When `op` itself does not build, or a join names a tool tree the engine lacks (`missingTool`), nothing is kept. With `tools`, a tool's step edited from this tree's history ("A tool's steps in History"): each entry is one tool tree's part, deepest first, built the same way before this tree's, and each part after the first, and this tree's `op`, must be a join naming the tip (the last id) of the part before. A tool tree or parent the engine lacks is `missingTool` before anything is built. A tool part whose replay breaks is kept broken, and so is the join it fed, which has no tool to take ("The tool object's step could not be rebuilt: …"), with that tree's replay unbuilt under it; this tree then shows the join's parent. When a part's own `op` does not build (the edited step, or a join whose tool built), nothing is kept in any tree. The reply adds `tools: [{key, built, broken?}]` in the order sent. |
| `goto` | `key`, `node`, `chordMm` | That node's reply. |
| `drop` | `key`, `node` | `{dropped, current}`. The node and everything under it go; the current node moves to the parent if it was inside. The root cannot be dropped, nor a branch with a step another tree's join takes as its tool. |
| `close` | `key` | `{ok: true}`, or a refusal while another tree's join takes its tool from this one. |
| `distance` | `key`, `node`, `aKind`, `aIndex`, `bKind`, `bIndex` | `{id, distanceMm}`. |
| `export` | `key`, `node` | `{bytesBase64, byteLength}`: AP214 STEP of that node. |

`open` reads STEP so that facet shells that sew into closed solids open as solids, and surfaces that do not open for measuring only. On such a root every `apply` and `probe` answers the refusal ("This STEP file has surfaces but no closed solid, so it can be measured but not edited.") before anything is built.

`op` is one of `{kind: "boolean", op, ...primitive}`, `{kind: "hole", origin, axis, radius, depth, through?, counterboreRadius?, counterboreDepth?}` ("Hole"), `{kind: "split", origin, normal}`, `{kind: "fillet" | "chamfer", edges, size}`, `{kind: "scale", factor}`, `{kind: "join", op, tool, relative, keepTool}` ("Booleans between objects"), or `{kind: "root", ...primitive}`: a new solid's primitive built again from other numbers in place of the solid above, which is how an edited primitive root forks ("Editable history"). A `root` step is refused anywhere but right under the root.

A primitive is `{primitive, origin, turn, ...}` in millimetres, with the fields its kind reads. Every kind but a sphere turns about its centre by `turn` (degrees about X, then Y, then Z). The newer fields are stored only when sent, so a box, cylinder, or sphere op reads and stores as it did before they existed. The engine checks every size and answers a refusal in plain words ("A cone needs a height above 0", "The tube's inner radius must be smaller than its outer radius", "A polygon needs 3 to 64 sides"); `tests/primitives.rs` lists them all.

| `primitive` | Fields | Sits | Built with |
|---|---|---|---|
| `box` | `size` | from `origin` along +X, +Y, +Z | `BRepPrimAPI_MakeBox` |
| `cylinder` | `radius`, `height` | `origin` is the bottom centre, up +Z | `BRepPrimAPI_MakeCylinder` |
| `sphere` | `radius` | `origin` is the centre | `BRepPrimAPI_MakeSphere` |
| `cone` | `radius` (bottom), `topRadius`, `height` | as a cylinder. Either radius may be 0, not both; equal radii build a cylinder | `BRepPrimAPI_MakeCone` |
| `torus` | `radius` (the ring, to the tube's centre), `tubeRadius`, smaller than the ring | `origin` is the centre, the ring flat in XY | `BRepPrimAPI_MakeTorus` |
| `wedge` | `size`, `topX` from 0 to `size[0]` | as a box; the top face runs from `origin`'s X for `topX`, so 0 is a ramp and `size[0]` a box | `BRepPrimAPI_MakeWedge`, its narrowing axis laid along Z |
| `polygon` | `sides` (3 to 64), `across`, `flats`, `height` | as a cylinder, one flat facing −Y. `across` is the width across corners, or across flats with `flats: true`, as a nut is sized | `BRepBuilderAPI_MakePolygon`, a face, `BRepPrimAPI_MakePrism` |
| `tube` | `radius` (outside), `innerRadius`, smaller, `height` | as a cylinder. An inner radius of 0 is a cylinder | the wall's section turned once about the axis (`BRepPrimAPI_MakeRevol`): one solid, not a cut | A fresh fillet or chamfer may name edges by index. The stored op names each as `{index, mid, lengthMm}`, where `mid` is the point at the middle of the edge's parameter range. A rebuild takes the index when its midpoint and length still agree within 0.001 mm, else the one edge that matches them, else the node is broken.

A reply is the node's tessellation with `id` set to the node and `format: "lime-solid-2"`. The client reads no array from a reply without that format and says the modeler does not match the app (`src/model-reply.ts`). The bulk arrays are base64 of little-endian words, decoded straight into typed arrays that view the bytes in place:

| Field | Words | What |
|---|---|---|
| `positions` | f32 | Nine per triangle: a triangle soup, wound outward. |
| `triangles` | u32 | The face index of each triangle. |
| `edgePoints` | f32 | Every edge's polyline, one after another, three per point. |
| `edgeOffsets` | u32 | One more than the edges: edge `i` is points `edgeOffsets[i]` up to `edgeOffsets[i + 1]`. |

The client keeps all four as f32 and u32, so the words lose nothing it reads. The rest is JSON, since it is small and kept as f64: `volumeMm3`, `solid` (false for surfaces with no closed solid), `faces` (`{areaMm2, normal?}` by face index; `normal` is the outward unit normal at the face's middle), `edgeLengths` (by edge index), `fingerprint: {volumeMm3, faces, edges}`, `replayed` (how many steps were rebuilt to answer it), and `held` (the nodes of this tree that keep a solid). The Open CASCADE version is in `lime_model_occt::stats()`, not in a reply. A missing tree answers `{error: "unknown", missing: [0]}` and a missing node `{error: "unknown", missing: [id]}`, so the client sends the root and the ops again. A step that fails to rebuild, or rebuilds to a different fingerprint, answers `{error, broken: id}`; that node and everything under it lose their solids and stay unbuilt until it is dropped.

What is kept, per node:

- The solid, with its face and edge maps and the volume the op integrated. Each tree pins its root, its current node, and every eighth node on the path between them. The 24 most recently used other solids stay; older ones are evicted and rebuilt on demand from the nearest kept ancestor.
- The fingerprint, for as long as the node exists. Every rebuilt step is checked against it.
- The reply, per chord, as it is sent, for the 8 most recently viewed nodes across all trees. A jump to one of those does no kernel work; the bridge copies the cached reply once, into its answer, and the loader copies that answer out of the bridge.
- With the solid, from its first reply: its face areas and normals and its edge lengths, and the chord its faces were meshed at. A reply built again at that chord, for a jump to a node whose reply left the cache, neither integrates a face nor meshes again: 1 ms instead of 84 ms on Telo test.
- An edge's midpoint and length, computed the first time a fillet or chamfer asks.

What is skipped: a rebuild tessellates only the node asked for, never the steps on the way. A split's other piece is tessellated once, for the apply that made it. Jumps never send it again, and replaying the split never touches the piece's own tree. Jumping above a split leaves both pieces in place.

Every call holds the tree's lock for its whole run, so tree calls run one at a time. Booleans and the split run non-destructively, so building a child or a probe never changes its parent's tolerances. STEP reads and writes take a lock of their own as well, because Open CASCADE keeps their settings globally.

## History tree (client)

`src/model-request.ts` builds every request the client sends, so a check against the real engine can build the same ones. `src/model-tree.ts` is the tree as data: nodes with their op, label, and fingerprint, `current` (what Model shows), `committed` (what the plate holds), and which child Redo follows. `src/app/model-trees.ts` keeps one tree per plate object, by the key the object carries as `modelTree`; the engine uses the same key.

- **Apply** sends `apply` with the shown node as `parent` and a fresh id, and shows the new node. From a node that has children it starts a new branch and Redo follows it; the old branch stays. Numbers already applied from this node jump to that step instead of building it again.
- **Undo** jumps to the parent and **Redo** to the child last applied or jumped through; the buttons, Ctrl+Z, and Ctrl+Y do this. At the root Undo is off, and Ctrl+Z in Model never reaches Prepare's history.
- **A jump** to one of the four nodes shown last draws the solid the client kept and asks the engine nothing. Any other jump asks `goto`.
- **The plate commits lazily.** Apply and jumps change only the tree and the view. The plate takes the shown node when Model closes, and before a slice, a G-code or 3MF export, a send to the printer, a project save, a switch to another object, a duplicate, or Arrange. Committing saves the paint, support edits, and placement scale of the node it leaves, and puts back those of the node it takes, if the plate held it before. A node the plate held keeps its mesh bytes, so going back to it gives the plate the same bytes, and a slice of them is found in the cache. Each Model visit that changed the plate is one Prepare step, and Prepare undo of it finds its node again by the mesh it restores, in any tree of that object. When the plate takes a node below a split whose piece a Prepare undo took off, the piece comes back.
- **A copy** of an edited object (Duplicate) gets a tree of its own, rooted in the STEP of the step it copies, or in the primitive when it copies a new solid's root.
- **A forgetful engine** (a restarted `serve`) answers `{error: "unknown"}`. The client opens the tree again with the root STEP, or the root primitive and its fingerprint, and every saved op, then asks once more. A primitive root that builds to another fingerprint is broken with everything under it, as a step is. A split piece's tree comes back by running its split again on a spare node of its parent tree, which is then dropped.
- **A broken node** (`{error, broken}`) is marked with everything under it; the readout says the step cannot be rebuilt, and the client does not ask for it again.
- **Release.** A tree stays while a plate object or a Prepare step can reach it as Model would find it: by its key; by a step whose plate mesh the object holds, in a tree of that object (after a Prepare undo to before the object had a key); for an object with no key, by any tree with its mesh (a copy finding the step it copies); and from each of those, the tree a piece was split from, the pieces its splits made, and the trees its joins take a tool from. Each time a Prepare step lands (which can push the oldest step out or clear the redo steps), the other trees are dropped here and closed in the engine. So a removed object's tree stays exactly as long as Prepare undo can bring the object back, or a join names it.

### Saved with the project

A project saves each plate object's tree as `modelTree`, next to its `brep` ("STEP save"):

```
modelTree: {
  nodes: [{ id, parent, op, name?, fingerprint, piece? }],   // root first, parents before children
  current, committed, nextId,
  rootStep: { name, bytesBase64?, byteLength, hash }   // or, for a new solid:
  rootPrimitive: { primitive, origin, size, radius, height, turn, ... }
}
```

- `op` is the op as the engine stored it, so a fillet or chamfer keeps each edge as `{index, mid, lengthMm}` (a bare index only if the engine did not echo the op). Labels are not saved; they come from the ops, and the root's from the object's name, or from a new solid's primitive.
- A new solid's tree keeps `rootPrimitive`, the primitive as the engine stores it, a few bytes instead of a STEP, and no `rootStep`. It is saved even with no step after its root, since there is no file to open it from again. A tree with both, or a damaged primitive, is a damaged tree. Files with `rootStep` read as before.
- `rootStep` is written once per tree. When the file already holds those bytes (the object's own mesh or `brep`, another object's, or an earlier root, as for a copy), it is written without `bytesBase64` and read from the record with the same hash and length.
- A split piece's tree is saved with the STEP of its own root (written at save if Model has not written it), so it opens without the part it was cut from. A split names its piece by the piece's plate object id, and only while that object is on the plate and its tree is saved. If the engine cannot write the piece's root, that tree is not saved, a notice after the save names the part, and after a reopen its split no longer counts as having made a part.
- Saved: the tree Model would resume for the object's mesh (by its key, or the object's other trees as after a Prepare undo), when it has a step, a name, a piece that a saved split names, or a primitive root. Not saved: engine keys, shapes, replies, broken marks, which child Redo follows, and the paint and meshes of steps the plate does not hold. Trees of objects that are no longer on the plate are not saved, but for a tool's that a saved join names (`modelTools`, "Booleans between objects").

On open, each tree gets a fresh key (`freshTreeKey`), so a file opened twice, or two files one after another, never meet in the engine. Nothing is sent until Model needs a step. The plate's step opens from the object's `brep` alone, as a STEP file does, and the engine numbers it as its root (node 0) while the client keeps its own id: enough to look at it, measure it, and check an edit. A call on any other step, and any Apply, first opens the whole tree: `open` with the root STEP, every saved op, and `current` set to that step, which the engine rebuilds from the root and checks against its fingerprint. Calls made while that open is on its way wait for it, and share it; a call sent before it but answered after it is asked again, since the engine need not run calls in the order they were sent. An edit never builds on the STEP-read solid, because an STEP round trip moves it: Telo test read back 14893.28 mm³ for a step built at 14893.51, and a hole on the read solid came out at 14410.32 mm³ where the same hole on the rebuilt step gives 14893.57. So the first Apply after a reopen says "Rebuilding the steps…", shows the step as rebuilt, then applies; a fillet or chamfer asks for its edges again, since the read solid numbers them its own way. If the step no longer rebuilds, nothing is built and the view goes to the last step that does. The solids and kernel answers kept from the read solid are dropped then, and a read solid still on screen is replaced before any edit. A tree whose plate step is the root, whose file has no `brep` (the engine could not write the plate's step), or whose root is a primitive, opens whole at once: a primitive root is a few numbers, and an edit would rebuild from it anyway, so no STEP is read. After an engine restart, a tree still on its read step opens from that STEP again.

After a reopen no Prepare step from before the save exists, so Delete branch keeps the root, the branch with the plate's step or the shown step, and a split whose piece is on the plate. A tree the file cannot read (a missing parent, an unknown op, a plate step not in it, a damaged or missing root STEP) is left out: the part opens from its mesh and `brep`, and one notice names it.

## History panel

The open solid's tree is a panel at the bottom left of the Model canvas, under the open tool and above the size chip and the readout (`src/ui/model-history.ts`). The four share one column, so a long warning in the chip or the readout pushes the panel up rather than run under it; on a short canvas the panel gives way first and scrolls, and while a tool is open it keeps to half the column. A long root file name ellipsizes, with the whole name in the tip. At phone width the chip and the readout sit under the toolbar, in the left half so they stay clear of the dock, and the sheet fills the bottom up to them, shrinking and scrolling rather than covering them. `src/model-history.ts` is its layout as data: one row per node, oldest first, drawn as a git graph. The shown step's path runs down the main rail; a fork lists its side branches right under it, each in a column of its own. A join is a merge: its tool's steps come in on a lane of their own ("A tool's steps in History"). The shown step has a filled dot and a bold label, the steps Redo would walk are dimmed, a broken step has a warning icon with its message on hover or focus, and the root is the file name. While the view shows a step other than the one the plate holds, the plate's row has a "Plate" chip.

- **Position** is a fixed row under the header, above the root and apart from the tree; collapsing folds the tree only, so it shows even then. On a short canvas History keeps room for its header, this row and one row of the tree, and with a tool open it may take half the column plus this row. It shows the open object's pose in model space as Place's fields read it, X, Y and Z from where its file put it and the turns, each only when it is not 0 at the panel's precision ("X 10 · Turn Z 30°"), or "At file position". A click opens Place. Reset, shown while the pose is not exactly the identity (so a pose a hair off still reads "At file position" beside it), opens Place, which closes another tool or an edited step whose checked numbers were for the old pose, and puts the part back where its file put it as one Place step: while Place is open Undo takes it back, and it is a Prepare step folded into the visit like a Place gesture, so Prepare undo takes it back too. The row is not a node: no jump, rename, menu, Delete branch or Edit step; it is a group of two buttons outside the `tree`, so the tree's keys never reach it and Tab does. Its text is formatted from the pose the plate object holds and the solid's own box, read once per solid, and only that text changes while Place drags, so the rows are never rebuilt for it. It asks the engine nothing.
- **Labels** come from the op with the panel's number format: "Cut box 10×10×10", "Fuse torus ⌀16 tube ⌀4", "Cut hexagon 5.5 across flats h 2.4", "Hole ⌀5 depth 8", "Hole ⌀3.4 through, counterbore ⌀6.5 × 3.4", "Fillet 3 edges r 1", "Split at Z 42", "Split at Z 42, tilt 15° / 0°", "Scale 200 %", in the part's own frame ("Model space"). A row's tip has its whole label, since a long one ellipsizes. A renamed step (double-click the label, or F2) shows its name, and the op is in the tip after it. The name is saved with the project.
- **Moving.** A click or Enter shows that step. Up, Down, Home, and End move and show the step after a 200 ms pause (`JUMP_WAIT_MS`), so a run of presses asks the engine for the last one only. Left and Right switch to the next branch at the nearest fork, at the same depth or that branch's last step. A newer jump wins over one still on its way: the late reply is kept in the client's recent solids and not shown. A step already on its way is not asked for again. While a jump is on its way, Apply, Undo, Redo, and STEP are off. A press still in its pause when Model closes does nothing.
- **Rows do not move under the pointer or the keys.** While the pointer is over the panel or focus is in it, each fork keeps the branch it followed; when both leave, the shown step's path moves onto the main rail.
- **Delete branch** (the row's menu, or Delete) drops the step and everything under it, here and with the engine's `drop`. It is refused, with the reason in the menu and the readout (in the sheet at phone width), for the root, a branch that holds the shown step or the plate's step, a branch with a step the plate held before (a Prepare undo can put its mesh back), and a branch whose split made a part of its own. There is no undo for it, so it asks for no confirmation. Model never closes a tree because the plate's mesh is not in it: a Prepare undo or redo can bring one of its meshes back.
- **Edit step** (the row's menu, the pencil on the row, or Shift+E) opens the step's tool with its numbers ("Editable history").
- **Keys.** Shift+H goes into the panel from anywhere in Model, opening it if needed, and back out; Esc leaves it. Shift+F10 or the menu key opens a row's menu. The list is a `tree` with `treeitem` rows (`aria-level` is the branch depth, a fork has `aria-expanded`, the shown step is `aria-selected`) and one row in the tab order. Branches never fold away, so a fork stays expanded, and Left and Right switch branches instead of folding them. The tree is `aria-busy` while an arrow press waits out its pause. Leaving the panel puts focus back where Shift+H came from, else on the canvas.
- **Collapsed** to its header ("History · 7") it stays collapsed for that browser (`localStorage`). At phone width it is a sheet over the canvas, opened from the History button in the Model toolbar.
- **Cost.** Rows are patched by node id when the tree value changes, and not built at all while the panel is collapsed, the sheet is closed, or Model is hidden. Drawing asks the engine nothing.

## Editable history

A step's numbers can change after it was applied; the owner asked for it on 2026-10-15. An edit never rewrites a step, since node ids are named by the plate's step, by split pieces, by kept joins, by Prepare undo and by saved files. It forks, as a new edit from an older step always has: the edited op is a new sibling of the step, the steps below replay under it as new steps, and the old branch stays as it was, for Delete branch to remove (`src/model-edit.ts`).

- **Opening.** Edit step in a row's menu, the pencil a row shows on hover or focus, or Shift+E: the focused row while focus is in History, else the shown step (and nothing while an edit is open, since the step shown then is the parent). Double-click stays rename. The step's tool opens with the numbers it was applied with, taken back into model space at the object's pose (`fromSolidOp`, the inverse of `toSolidOp`), under a header such as "Editing step 3: Hole ⌀5 depth 8". The view shows the step's parent, with the tool's ghost and handles, as when the step was first applied, and the dry-run runs on the parent. Apply reads Update, and stays off while the panel still says the step as it is ("Change a number to update this step."), so an untouched panel asks the engine nothing. A field left alone sends its stored number exactly, though it shows it to the hundredth. Cancel, Esc, or another tool puts the view back where it was; a click on a step in History goes there instead. While a step is edited, Undo and Redo are off, and Delete branch keeps the branch with the step edited or the step Cancel goes back to. A save while a step is edited saves the step shown before the edit as the shown one. A tree from a project still on its STEP-read step opens whole first, as for an Apply.
- **What changes.** A boolean: its op, its primitive, sizes, origin and turn, but not Object. A hole: origin, radius, depth, Through all, the counterbore's box and numbers, and its drill direction, kept until a face is picked. A split: shown on the model axis its normal is nearest, with the tilts from it and the plane's position on the line through the part's middle; a normal pointing down that axis keeps its side. A fillet or chamfer: its size and its edges, picked again for the panel by midpoint and length on the parent (the readout says how many are no longer there). A scale: its factor. A join: Fuse, Cut or Common, and Keep the tool object; its tool object and step stay as applied, and to change them the step is deleted and joined again. The tool's own steps are edited from their rows in the join's lane ("A tool's steps in History"). Update of a join with Keep off takes its tool off the plate if it is there, as Apply does; Keep turned on does not bring a tool back that an earlier Apply took off, which Prepare undo does. A new solid's root edits in New solid's panel and becomes a `root` step right under the root, so node 0 never changes. An opened STEP is a file, and a split piece's root is its split's: neither is edited (Edit step says why, and the row shows no pencil); nor is a step under a broken one.
- **Which steps replay.** The shown branch below the step: the path down to the step shown when that is below it, then on to the branch's tip; else the branch from the step. A branch goes on as History draws it, with the child Redo follows, else the newest, so a reopened tree, which knows only the path to its shown step, replays its other branches whole. A `root` step on the way is left out, since the edit's new root stands in for it. A step Redo would walk is part of the branch the user sees, so it comes along rather than stay behind. User names come along too.
- **Update** is one `edit` call. While it runs the readout says "Rebuilding 4 steps…"; the UI is not held, and Cancel goes back at once, to a step kept among the recent solids when the edit opened: what the engine built for it is dropped when its answer lands. The view goes to the last step that built, and Redo stops there. Numbers that already built a branch from the same step, with the same steps after it, show that branch instead of building it again.
- **A step that no longer builds** (a fillet whose edge is not on the new solid, a hole that misses) stops the replay. It is kept, broken, with the engine's message on its row and the steps after it under it, and the readout names it: "Step 4, “Fillet 1 edge r 1”, could not be rebuilt: That edge is not on this solid." It can be edited, which forks it in turn and replays what is under it, or its branch deleted. Nothing is skipped and no solid is guessed.
- **Undo** from the edit's tip goes back to the step shown before the edit, on the old branch, and Redo forward again; past that, Undo and Redo walk the tree as ever.
- **Split pieces.** A replayed or edited split builds its own side only and makes no new piece: a piece already on the plate is a part in its own right and stays as the older split cut it, which the readout says ("telo split stays as the older split cut it."), and so does Model each time it opens that piece while its part's plate step is not under the split that cut it. Re-rooting the piece on the new other half would replace a part behind the user's back.
- **Joins.** A join in another part that names a step of the edited branch keeps naming it, untouched; the readout says so.
- **Plate.** The plate takes the new tip by the lazy commit, in the visit's one Prepare step, and Prepare undo puts the old mesh back. A commit while a step is edited takes the step shown before the edit.
- **Saved.** Nothing new beyond the nodes and the shown step: a fork reopens with both branches, and a `root` step is saved as its op. An app from before this reads `root` as an unknown op and leaves that tree out, opening the part from its mesh.
- **Cost.** The parent's kept solid is the start, a kept probe of the edited op is reused, no replayed step but the last that built is tessellated, and the panel's numbers are worked out once, when it opens.

## A tool's steps in History

A join used to show as one row, and its tool usually leaves the plate, so the tool's steps could be neither seen nor edited. The owner asked on 2026-10-16 not to lose them, and approved both parts below, as Fusion and Onshape keep a combine's tool body with its features and recompute the result when one changes (`src/model-history.ts`, `src/model-edit.ts`).

- **The lane.** Right above each join, the tool's steps from its root to the step the join takes come in on a column of their own and merge into the join's row, as a merged branch does in git. The lane shows that path only, the history that made the tool as the join took it; the tool's other branches, and its steps after that one, belong to the tool object's own History. Every join has its lane, on any branch: on the shown step's history it is lit as the rest of that history, elsewhere it is dim. A tool's dots are hollow, and the lane's first row carries the tool's name (unless that row's label is the name already). A tool whose own history has joins nests their lanes in its lane, to any depth; the cycle refusal per tree ("Booleans between objects") keeps the nesting finite. A tool tree the app does not have draws no lane.
- **A click on a tool's row** (or Enter, or an arrow after its pause) shows the tool as it was at that step, read-only: its solid where the join put it (the open object's pose, then each join's `relative` in turn, `toolPose`), with the open solid grey behind it as it was on screen, the tool's own plate object, if Keep left one, hidden so it does not stand in the way, and the other objects grey. Nothing else moves: the open solid's shown step and plate step, its Redo, and the tool's own tree (its shown step, plate step and Redo) stay as they were, and the Plate chip marks the step the plate holds. The tools wait, each tip saying why, and picks are off; New solid stays. A click on one of the part's own steps, or Esc on the canvas, goes back to the part; Undo and Redo step the part's own history as ever, from the step the part shows, and so leave the tool's step too. Deleting the branch of the join whose tool is looked at goes back to the part. The step's solid is asked of the tool's tree once (`goto`) and kept among the recent solids.
- **What a tool's row allows.** Edit step, from the pencil, the menu or Shift+E, as below. Rename renames that step in the tool's tree: it is the same step the tool object's own History shows, so it reads the same in both, and no plate changes. Delete branch is off, with the reason in the menu: every row of the lane is on the way to the step the join takes, which the engine keeps while the join names it; deleting the join's branch is the way.
- **Edit step** opens the step's tool on its parent in the tool's tree, shown where the join put the tool, with the step's numbers in model space at that pose, under "Editing Rod 1, step 1: Scale 150 %" (or "Editing Rod 1's primitive: …" for a New solid tool's root). The dry-run runs on that parent, in the tool's tree. Update is one `edit` call with `tools` (`crossEdit`, `crossEditRequest`): the tool's tree forks at the step, the edited op a sibling of it, and replays down to the step the join takes; each join above is built again on the new tip, as a sibling of itself, its tree replaying down to the step the next join takes; and the open solid's steps after its join replay as Edit step replays them. The old branches stay in every tree, for Delete branch. The view goes to the open solid's new tip, and Undo goes back to the step shown before the edit, as for any edit. Numbers that built these branches before show them instead. The tool's tree takes the new branch without moving its shown step, its plate step, or which child its Redo follows from the step edited, so the tool object's own History keeps its shape.
- **One call, not two.** Two calls composed by the client would leave the tool's new branch behind whenever the second failed, or the app or the engine stopped between them, and that branch would then need a cleanup that can fail too. One call under the engine's lock keeps a failure clean: when the edited step, or a join whose tool built, does not build, nothing is kept in any tree and the readout says why, as for an edit of the part's own step. A tool step that no longer builds is a broken replay like any other: it is kept broken, the join it fed is kept broken too ("The tool object's step could not be rebuilt: …") with the part's later steps unbuilt under it, the view shows the join's parent, and the readout names the tool's step: "Step 2 of Rod 1, “Hole ⌀4 depth 12”, could not be rebuilt: …". That step can be edited from its row in turn.
- **The tool object on the plate** (Keep ticked, or brought back by Prepare undo) keeps its own plate step: a fork in its tree moves neither its plate nor its shown step. The readout says so: "Rod 1 on the plate keeps its own steps; only this part's join takes the edit."
- **Saved.** Nothing new in the file: the tool's tree is saved with its new branch, in `modelTools` or with its object, and the join names the new step. A reopened project draws the lanes and opens a tool's tree when one of its rows is first shown or edited, the whole tree first for a tree still on its STEP-read step. An app from before this reads the file as before.
- **Keys and ARIA.** A tool's rows are `treeitem`s one level below their join, which owns them (`aria-owns`) and is `aria-expanded`, so a screen reader hears them as the join's children though they are drawn above it; each reads as "Rod 1: Scale 150 %". Up and Down walk every row in order, a tool's included. Right on a join goes into its lane, to the step it takes, and Left on a tool's row comes back to its join, as a tree item's children are reached; so on a join, Right no longer switches to a branch on its right, which Left and Right still do everywhere else. Rows are named by their step and the joins they are reached through (`RowKey`, "2/1": step 1 of the tool the join at step 2 takes).
- **Cost.** The lanes are laid out with the rows, only when the open tree, a tree its joins reach, or the row on screen changes: never per frame, per hover or per Place drag. Nothing is asked of the engine for a row until it is clicked or edited.

## Viewport handles

Every Model tool is both typed and dragged. Each number in the open tool's panel has a handle in the viewport, drawn in Prepare's gizmo style, and a drag writes the field as if it were typed. The ghost, the dry-run, and Apply follow, and a typed number moves the handle. Shift slows the pointer to a tenth for fine control, and Ctrl (Cmd on a Mac) snaps to the handle's step: 1 mm, 0.5 mm for a blend or hole radius, 0.1 for a scale factor, and 15° for a turn. A label by the pointer shows the value. The panel's scrub labels use the same keys.

| Tool | Handles |
| --- | --- |
| Boolean | X, Y, Z arrows on the primitive's origin, a knob for each of its sizes (out along the primitive's own axis that size grows along; a second size on one axis takes the next axis, and a wedge's Top X leans up from Size X), and three turn rings on every primitive but a sphere |
| New solid | the same size knobs, unturned; it places itself, so it has no arrows or rings |
| Split | an arrow on the plane's pivot along its normal, held between the face margins, and two tilt rings on the dock |
| Fillet, Chamfer | a size knob out from the picked edge's middle |
| Hole | a dot that slides the origin over the solid, plus radius and depth knobs (no depth knob with Through all); with a counterbore, a Bore radius knob on the next axis and a Bore depth knob on the drill axis, nearer the dock's middle than Depth's |
| Scale | a factor knob on the diagonal from the centre |
| Measure | two dots, A and B, that slide over the solid; the note reads the distance and ΔX, ΔY, ΔZ |
| Place | X, Y, Z arrows and three turn rings on the dock |
| Workplane | U, V, W arrows that slide the frame's origin, and three turn rings, on the dock |

A primitive turns about its centre by Turn X, then Y, then Z, in degrees: a box's or a wedge's middle, a torus's centre, or halfway up the axis of the others (`turnCentre`); the kernel builds the primitive and applies the same rotation before the boolean. A sphere does not turn. Measure and Place have no Apply. A hole that would miss the solid starts on the middle of its top; on a local workplane, at the frame's origin, or on top along W when nothing is behind the frame. `src/model-drag.test.ts` fails if a toolbar tool has no handle, or if a number in its panel cannot be dragged.

Handles that move, turn, or size the tool's object sit on a fixed dock at the right edge; handles on a picked feature stay on the solid. The dock's seat (`dockSeat` in `src/gizmo-math.ts`) keeps its whole reach, the knobs' grab spheres as the perspective view draws them, 24 px inside the right edge and clear of the toolbar, the Measure chip, and the view cube. It depends only on the canvas size, the field of view, and the handle size, so orbit, zoom, and pan never move it; it is worked out again when the canvas is resized. A canvas too small for the full dock shrinks its handles, down to 48 px, rather than cut them off, and at 48 px the dock still stays right of the middle.

## STEP save

Model mode writes the open solid as AP214 IS, a manifold solid B-rep, through `STEPControl_Writer`. The STEP button downloads that file. The same bytes are kept on the plate object as optional `brep`, in the same shape as `mesh`: name, base64, length, and hash. An edit does not write them. The STEP of the node each plate object holds is written when it is needed: leaving Model (in the background), a project save, and the STEP button (which writes the shown node). A written STEP goes to every plate object and Prepare step whose mesh token (`meshTokenOf`) is that node's mesh, so a step captured before the write gets it too, and to the node, so the plate gets it back when it returns there. Prepare steps share each STEP buffer rather than copy it. A solid the engine can no longer write loses its `brep` at save rather than keep one from an older shape. Prepare history folds a Model visit that changed the plate into one step on leaving Model; the tree keeps the steps in between.

`.lime` stays version 2. A one-object file with `brep` or `modelTree` is version 2 so the field is not dropped. The tree's format is under "Saved with the project". A file without it still opens, including one saved before this field existed. A damaged `brep` fails the open. An older app ignores the keys, slices the mesh, and drops `brep` and `modelTree` on the next save. Duplicate copies the bytes. The second piece of a split gets its own `brep` when its STEP is written.

Opening Model reloads `brep` when the object has one, so an edited solid is not stuck as a mesh. The STL is what the slicer reads. Opening Model still does not replace `sourcePos`.

## What this change is not

- No change to `tools/golden_ab.sh` or to slicer output.
- The slicer core does not link Open CASCADE. Truck still reads an unedited STEP file for slicing.
